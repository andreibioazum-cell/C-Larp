# Архитектура Cubic Battle 4

## Слои

Проект разделён на четыре слоя с односторонними зависимостями:

1. `src/game` содержит правила и состояние Cubic Battle 4. Он использует
   публичные функции движка, но не обращается к Android API напрямую.
2. `src/engine` содержит графику, звук, сеть, шрифты и общий рантайм. Код этого
   слоя не зависит от игровых экранов и боевых правил.
3. `src/platform/android` реализует нативный цикл приложения и адаптеры Android
   для клавиатуры, HTTP и аудиовывода.
4. `platform/android` содержит только файлы упаковки APK: manifest, Java-мост и
   Android resources.

Исходные игровые данные находятся в `assets` и не смешиваются с C-кодом.
Сторонние библиотеки изолированы в `third_party`.

## Игровая логика

`src/game/game.c` является unity-точкой сборки. Внутренние функции подсистем
объявлены `static`, поэтому наружу экспортируются только hooks из
`src/game/game.h`:

- `game_init`;
- `game_update`;
- `game_draw`;
- `game_touch`;
- `game_back`;
- `game_reset`.

Логика разбита по назначению:

- `core` — конфигурация, сущности и основной цикл;
- `ui` — экраны, локализация, прогресс, чат и ввод;
- `combat` — движение, атаки, способности, бот и сетевой бой;
- `fx` — снег, пыль и эффекты окружения;
- `state` — глобальное состояние, его создание и освобождение.

Unity-сборка выбрана намеренно: она сохраняет закрытые связи между игровыми
модулями и не требует общего глобального API для сотен внутренних функций.

## Движок

- `graphics` записывает команды отрисовки и выполняет их через Vulkan;
- `audio` декодирует WAV, смешивает голоса и передаёт PCM платформе;
- `network` отвечает за Firebase, комнаты, чат и постоянные данные;
- `runtime` предоставляет массивы, строки, журнал и защищённые вызовы hooks;
- `font` загружает TTF и создаёт растровый атлас символов.

Файлы `src/engine/*.c` являются точками сборки соответствующих подсистем.
Платформенные реализации подключаются из `src/platform/android`.

## Ресурсы

Исходное дерево ресурсов организовано по типу данных:

- `assets/textures` — PNG;
- `assets/audio` — WAV;
- `assets/fonts` — TTF и лицензии;
- `assets/shaders` — GLSL.

`stage_assets.py` преобразует его в структуру Android assets. Исходная
структура при этом остаётся удобной для разработки, а runtime получает
стабильные пути, совместимые с существующей игровой логикой.

## Ограничения зависимостей

- игровая логика не включает Android и JNI заголовки напрямую;
- Java не содержит игровых правил;
- движок не включает файлы из `src/game`;
- исходные ресурсы не размещаются рядом с C-модулями;
- генерация игровой логики при сборке запрещена;
- один собственный исходный файл не должен превышать 450 строк.
